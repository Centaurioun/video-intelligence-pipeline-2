# VIP B-first pinned synthetic video fixture and strict admission design

**Date:** 2026-11-06
**Status:** Proposal only — exact owner authorization required before fixture bytes, generator execution, source/CI changes, or runtime use.
**Scope:** One tiny immutable synthetic video fixture and a future additive `analyze-local` fixture-ID route for local developer regression.
**Terminal disposition:** `BFIRST_PINNED_VIDEO_FIXTURE_DESIGN_PROPOSED — BOUNDED_SOURCE_EXECUTION_PENDING`.

## Decision summary

Adopt a reviewed **CI artifact pinned by exact producer identity and content digest** (B2) for the first fixture, registered by a closed `fixture_id` in the trusted fixture policy. The policy pins workflow source revision, run ID, artifact ID, CI-reported archive digest, extracted MP4 SHA-256 and byte count. GitHub's upload-artifact v4+ documentation describes uploaded artifacts as immutable and exposes artifact IDs and SHA-256 archive digest, but also allows overwrite by replacing with a new ID, applies retention periods, and permits artifact deletion; the artifact URL depends on artifact/run/repository still existing. The archive digest is not the extracted MP4 digest. The task packet must verify the configured action version and current platform guarantees, record the expiry/retention deadline, verify both archive and extracted-file digests, and refuse after expiry rather than regenerate silently. This respects the current Gate-0 fixture rule that checked-in media is forbidden. The artifact is not cryptographic proof of synthetic origin: the local trust model assumes reviewed workflow code and an honest runner. A same-user adversary who controls checkout, Git refs, executable, artifact cache, and policy can replace them. If artifact identity, retention window, and digest provenance cannot be independently verified, strict execution remains `BLOCKED_TRUST_ANCHOR`; do not silently switch to a Git blob. Reconsider B1 only after a separate explicit exception to the no-committed-media rule. ([upload-artifact README](https://github.com/actions/upload-artifact#-not-uploading-to-the-same-artifact), [GitHub artifact retention docs](https://docs.github.com/en/actions/using-workflows/storing-workflow-data-as-artifacts#configuring-a-custom-artifact-retention-period))

The first case is a proposed 64×64, short, constant-frame-rate MP4 with a single video stream, no audio, and at least two distinct deterministic frames. The exact codec, dimensions, frame count, timestamps, stream index, file size, and digest remain **unmeasured** until a separately authorized generation and independent inspection. No video exists in the current reviewed fixture set: it contains JSON timing recipes; existing FFmpeg integration media is generated at test runtime and is lower assurance.

Strict admission selects `fixture_id` using independently pinned policy identity before any local media-byte read, probe, or indexing. The already-published artifact may be provisioned by the pinned CI step; external retrieval is not part of the strict CLI operation. A bounded private local snapshot is mandatory because the current FFprobe path accepts a filesystem pathname and reads that path itself; do not claim descriptor custody reaches FFprobe unless a future adapter is proven to accept the held descriptor. Stage C must safely copy the authorized artifact from the verified held descriptor to a private no-follow, no-clobber snapshot, enforce the byte limit, hash while copying, fsync, verify snapshot bytes/identity, and pass only that snapshot pathname to probe/decode/query. It never falls back to arbitrary `--source` or a self-authored legacy grant. Failure is closed and explicit. The existing legacy developer workflow remains a separate lower-assurance path until an independently approved migration.

## Goals, limits, and non-goals

Goals:

1. Give developers one real, decodable, immutable video input for regression of strict fixture-ID admission and report semantics.
2. Exercise the supported image-source query pipeline with deterministic fake embeddings, at least two ranked matches, and measured video-stream index, integer source PTS, and rational timebase.
3. Make policy identity, artifact identity, current file identity, and occurrence status separate and inspectable.
4. Fail closed before source-byte access when policy/ID authorization is missing or inconsistent.

Limits and anti-goals:

- Local regression only; not proof of authentic archive provenance, external signing, custody against a same-user attacker, production readiness, Gate progress, or release approval.
- No real model, provider, archive media, download, network operation, audio, editing, rendering/export, QC, scheduler, schema migration, or main merge.
- No VFR/frame-accurate claim, no fabricated interval, no conversion of semantic similarity into temporal or editorial authority.
- No dynamic strict-path media generation. Fixture issuance is a separate operation and authority from code that consumes the frozen bytes.

## Artifact and custody decision

### Alternatives

| Option | Advantages | Costs and failure modes | Disposition |
|---|---|---|---|
| B1: one-time generated, inspected MP4 checked in as a Git blob | Exact tree/blob identity; offline; reviewable alongside policy; straightforward source pinning | Binary diffs are opaque; history retains each version; Git does not prove origin; current Gate-0 generator explicitly says checked-in media is forbidden | Reject under current policy; only reconsider after explicit exception |
| B2: immutable CI artifact | Keeps binary out of source history; workflow run can identify producer | Requires immutable retention, artifact ID/digest pinning, trustworthy workflow and retrieval; a URL or mutable release tag is insufficient; adds CI trust dependencies | **Choose**, with fail-closed behavior if immutability/retention or independently pinned provenance cannot be verified |
| Generate at test runtime and self-hash sidecar | Simple, reproducible test setup | Manifest and bytes can share one untrusted invocation; tool drift; does not create a reviewed pinned source authority | Reject for strict admission; existing tests stay explicitly lower assurance |

The CI artifact is an artifact anchor, not an origin oracle. The policy must be independently selected by the developer/test launcher as an exact reviewed workflow revision/run ID/artifact ID plus expected CI archive digest, extracted MP4 SHA-256, size, and expiry/retention boundary; a digest embedded only inside a mutable manifest is circular. The policy contains a literal fixture ID, immutable artifact coordinates, expected digest/size, allowed purpose/operations, and finite processing limits. The CI workflow may provision the pinned artifact before tests using its platform-controlled artifact access; local strict execution may read only a previously provisioned artifact whose policy and exact coordinates were independently selected. Artifact expiry/deletion fails closed; no automatic re-generation or substitution is permitted. Absent artifact bytes fail as `BLOCKED_NO_PINNED_VIDEO_FIXTURE`. No identity may be synthesized from bytes at invocation time. These are proposed controls; current repository workflow configuration, retention setting, and artifact producer remain unverified.

Generation custody belongs to a named future fixture issuer, separate from the strict admission/CLI implementer. Reuse `tests/gate0/media/generated_media.py` as a reference only; do not modify it or import it as a strict runtime dependency. Its current harness explicitly says checked-in media is forbidden, while `build_media_corpus.py` builds a generated-media corpus, not a single pinned VIP video artifact. A new bounded generator is proposed at `tests/vip_fvs/fixtures/generated_video/build_pinned_video.py`, with its measured issuance receipt at `tests/vip_fvs/fixtures/generated_video/issuance-receipt.json`; generated video bytes are not committed. The issuer packet must record:

- exact generator script and source commit, and whether it is a narrowly written generator or a reviewed deterministic command;
- FFmpeg executable path, measured executable SHA-256, measured version output, and container/environment identity; do not infer codec support from a filename;
- full command arguments, environment, generation timestamp, and bounded output path;
- resulting artifact SHA-256 and byte count, measured from raw bytes;
- proposed generation limits: 64×64 pixels, 2 seconds, CFR 4/1, 8 frames, maximum 65,536 bytes; these are target bounds, not measured output properties;
- independent raw-byte and decode inspection receipt, with inspection tool identities and results, including stream count/type, codec, dimensions, frame count/duration, integer PTS and rational timebase;
- exact immutable artifact producer workflow revision, run ID, artifact ID, retention guarantee, and post-upload digest verification; exact workflow path is selected only after Stage A reviews the workflow inventory;
- a separate human visual observation of decoded frames if relied upon, labeled `VISUALLY_OBSERVED`; intended synthetic purpose is an assertion, not a measurement.

No exact size, hash, PTS, codec, frame rate, or stream index is claimed in this proposal. All are `NOT_OBSERVED` until issuance. Do not use a filename, manifest self-hash, generated-media sidecar, or codec heuristic as provenance.

## Initial fixture shape and report semantics

Proposed single case `bfirst_tiny_video_v1`: 64×64, 2 seconds, CFR 4 fps (8 frames), one video stream, no audio, deterministic distinguishable color/geometric content, and a 65,536-byte maximum. VIP's existing CLI test creates a 64×64 `mpeg4` color MP4 at 5 fps and exercises measured stream/timebase plus multiple report hits, but its clip is 20 seconds and generated at test time. The Gate-0 generator uses `libx264`, `yuv420p`, and CFR flags in its own harness. Neither source fact establishes decoder compatibility in the future Stage A environment; this session ran neither FFmpeg nor FFprobe. Propose MPEG-4 Part 2 (`mpeg4`) in MP4, without B-frame reordering, because the VIP CLI test already uses it; change codec only if the separately authorized encoder/decoder matrix demonstrates incompatibility. Exact size, codec, stream index, decoded frame count, PTS and rational timebase remain `NOT_OBSERVED` pending Stage A.

The purpose is specifically to pass real decoded image samples through the supported source-query path while removing model nondeterminism. Fake embeddings are fixed and deterministic, allowing a stable ranking assertion for at least two candidates. The report must use the exact measured absolute stream index and source-native integer PTS paired with the measured rational timebase. `MATCHED` semantic results remain nonbinding POINT evidence; measured media timing remains separate. Do not invent intervals, derive source time by multiplying a nominal FPS, or call semantic POINT a frame-accurate edit.

## Strict admission contract

1. Caller supplies only the closed `fixture_id` selector for strict mode. Launcher supplies or pins the policy revision independently. Resolve and validate exact policy revision/tree/path and producer workflow revision/run/artifact identity before opening any local media path.
2. Validate ID membership, purpose, operation, policy schema/version, and finite limits. Unknown ID, wrong policy revision, disallowed operation, missing trust anchor, or legacy strict-mode selector mismatch stops before video bytes are read, probed, indexed, or decoded.
3. Resolve the fixed relative path beneath a pre-approved fixture root. Reject absolute paths, traversal, symlinks, and unapproved roots. Open with no-follow semantics and bounded reads; retain descriptor custody. Record measured device/inode and exact opened bytes separately from policy `MATCHED` identity. Hardlinks require explicit rejection or proof the opened object is the pinned object under the platform's available semantics; default to reject unexpected link count where reliably available.
4. Verify exact size and SHA-256 against independently pinned policy, then copy only from that admitted descriptor to a bounded private no-follow/no-clobber snapshot. Enforce the 65,536-byte maximum while reading, hash during the copy, fsync the snapshot and directory, verify the snapshot digest/size/device/inode, and reject symlinks/replacement. The current `_fixture_source_probe` passes a `Path` into `probe_real_source`, which checks path and reads bytes from that path before invoking FFprobe; therefore Stage C must probe the private verified snapshot path. A direct held-descriptor FFprobe adaptation is an alternate only after a separately reviewed interface and tests prove the descriptor is the one consumed. The snapshot is not source occurrence proof.
5. Preserve the exact snapshot identity and revalidate it before and after probe, before indexing/query, and before publication. Do not reopen the original artifact pathname after admission. Any identity drift or uncertain snapshot durability fails closed.
6. Strict mode has no fallback to arbitrary `--source`, old synthetic grants, JSON timing recipes, or dynamically generated media. Legacy CLI remains separately labeled lower-assurance developer plumbing until an exact contract migration is authorized.
7. Publish report atomically with no-clobber behavior. Report exact policy revision and fixture ID; `MATCHED` pinned policy reference; measured opened-byte digest/size and file identity; source occurrence `NOT_OBSERVED`; evidence classes per assertion; source-native time data; deterministic fake embedder identity; and explicit local trust-model limitations.

If independent policy selection cannot be established, report `BLOCKED_TRUST_ANCHOR`. If a suitable pinned decodable video is absent, report `BLOCKED_NO_PINNED_VIDEO_FIXTURE`. Neither state is success. Maintain `STRICT_ANALYZE_LOCAL_VIDEO_NOT_OBSERVED` until the exact strict route is implemented and exercised; preserve `CORE01_LEGACY_INTERVAL_BLOCKED_BY_CONTRACT`.

## Adversarial acceptance matrix for future implementation

| Case | Expected result |
|---|---|
| Unknown fixture ID or missing independent policy anchor | Reject before any video open/read/probe; explicit blocked/refusal state |
| Wrong policy revision/tree/path or workflow/run/artifact ID; stale/edited policy | Reject before local video bytes; never trust a self-hash inside the policy |
| Correct ID, wrong digest or size | Reject before probe/decode/index/query; retain no report claiming acceptance |
| Same bytes copied into a second root | Content/policy may match; actual file identity differs; source occurrence remains `NOT_OBSERVED`; never infer custody from content equality |
| Artifact expired/deleted, wrong CI archive digest, or wrong extracted MP4 digest | Reject; no local substitution, regeneration, or success from receipt alone |
| Symlink, traversal, absolute path, or unexpected hardlink | Reject before reading outside approved root; no-follow descriptor checks must be observed |
| Replace/rename source after selection or during probe | Held descriptor/snapshot stays authoritative or operation fails on identity drift; pathname reopen must not redirect input |
| Corrupt or non-decodable MP4 with validly registered test bytes | Probe/decode failure is explicit; no semantic result and no partial-success report |
| Two or more ranked candidates | Stable fake-embedding ordering; each result carries nonbinding `MATCHED` POINT and measured source PTS/timebase |
| No video stream, wrong absolute stream index, or unsupported selected stream | Refuse with no query result; assert stream index comes from the probe and binds to snapshot |
| Missing, malformed, zero, or grant-mismatched timebase | Refuse; never infer source PTS from nominal FPS or accept caller-authored timebase |
| Zero-match query | Emit explicit zero-match state and deterministic persisted report digest; do not call it a match success |
| Top-K saturation/truncation | Stable ordering and configured bound; report does not imply exhaustive candidates |
| `source_kind=synthetic` label without registered fixture policy | Reject before bytes; source-kind is descriptive and grants no authority |
| Existing output path | No-clobber publication refuses; preexisting bytes remain unchanged |
| Strict request plus legacy `--source`/grant flags | Refuse ambiguous or mixed mode; no silent legacy fallback |
| Legacy-only request | Existing lower-assurance developer behavior stays distinguishable and cannot emit trusted-manifest acceptance |
| REAL mode or provider/model operation requested | Refuse before source read, model initialization, or network/provider access |
| Snapshot creation interrupted or output collision | Fail closed; no partial accepted snapshot; no clobber |
| Report hardlink publication succeeds but parent-directory `fsync` fails | Return/record durability as uncertain; do not claim success or durable report digest; retain evidence for reconciliation |
| Descriptor/source revalidation mismatch | Stop before indexing/query or report publication |

Tests must observe ordering, not only final exceptions: inject a source-open/read/probe spy and assert zero calls for pre-read authorization failures. Use filesystem race/adversary tests only in bounded temporary directories. No protected source material.

## Alternatives rejected and open owner choices

- Runtime generation is rejected for strict admission because it co-creates bytes and their claim in one invocation.
- A downloaded or mutable release URL is rejected as a trust anchor. B2 remains viable only with immutable artifact identity, digest, retention, and independently trusted workflow provenance.
- A signed receipt/PKI root is deferred as disproportionate to the honest-local-misconfiguration objective; reconsider only if the threat model changes.
- Filename, codec, pixel-pattern, or `synthetic` labels cannot prove origin and are not authorization.
- Multiple codecs, VFR, audio, B-frames, several fixtures, actual model embeddings, and real media are deferred to separately named tasks.

The owner must separately decide whether to authorize Stage A's one-time generation and immutable CI artifact issuance, including the 65,536-byte cap, proposed media shape/codec, exact CI workflow, artifact retention/immutability, FFmpeg/tool boundary, and nominated issuer. If B1 is preferred, an explicit policy exception to the current no-committed-media rule is required first. No implementation stage starts solely from this proposal.
